# manga-mobi2cbz

Kindle 漫画専用の一括変換 CLI ツール。ワンコマンドで DRM フリーの MOBI / AZW / AZW3 電子書籍を標準 CBZ コミックパッケージに書き出します。
OPF spine の公式読み順に従って画像を抽出し、表紙自動修復、同巻複数形式の重複排除、バッチタイムアウト保護、ファイル完全性検証、多言語自動出力などの実用機能をフル装備。パッケージ化せずに漫画のメタデータ・解像度・NCX 目次・DRM 状態を確認できる `--inspect` 検査モードも付属しており、全プラットフォーム対応で漫画ライブラリの一括整理を安定して効率化します。

> ⚠️ 重要な制限: DRM 解除済みの Kindle 漫画のみ対応。ストアで購入した暗号化電子書籍は解析できません。
> 
> ⚠️ リスク注意: 本プロジェクトは AI 生成です。ご利用は自己責任でお願いします。
> 
> 📝 備考: 個人利用を目的としたプロジェクトで、ファイル変換時に AI が生成したスクリプトを後から使えるように保存しています。

## 機能

- **一括変換** — 単一ファイルまたはディレクトリ全体を再帰的に変換（`.mobi` / `.azw` / `.azw3`）
- **OPF spine 順** — OPF spine の順序で画像を抽出し、実際の読み順を保証。OPF が無い場合はファイル名の自然順ソートにフォールバック
- **表紙フォールバック** — ファイル名に cover/front を含む画像を自動スキャン。表紙がすでに spine リスト内にあればリスト順を優先し、欠落時のみ先頭に補完
- **ディレクトリ整合フォールバック** — ディレクトリ内の画像数が収集数と一致しない場合、余分な画像はデフォルトで自然順に cbz 末尾へ追記。`--drop-extra` で破棄に変更可（処理結果は出力されます）
- **二重ディレクトリ重複排除** — mobi7/mobi8 の二重ディレクトリを自動検出し、デフォルトで mobi8 を保持（画質が良い可能性）。切替可能
- **軽量多言語対応** — `--language auto|zh-CN|zh-TW|ja|en` で出力言語を切替（デフォルト `auto` はシステム locale で自動判定: 簡体字中国語→zh-CN、繁体字中国語→zh-TW、日本語→ja、その他→en）。全出力文面と `--help` が言語に応じて翻訳されます（パラメータ名・列挙値・固有名詞は翻訳されません）
- **同名拡張子重複排除** — 同じディレクトリ内で拡張子だけ異なるファイル（例: `Vol1.mobi` + `Vol1.azw3`）は 1 つだけ保持。`--ext-priority` で保持優先度を制御（デフォルト azw3）
- **自然順ソート** — ページ番号で自然順ソートし、`10.jpg` が `2.jpg` より前に来るのを防ぐ
- **完全性検証** — 変換後に CBZ ファイルを自動検証し、破損時は削除して通知
- **無圧縮パッケージ** — 画像は既に圧縮済みのため、ZIP はデフォルトで保存のみ（store）。高速・小サイズ
- **任意圧縮** — `--compress LEVEL` で deflate 圧縮（1-9）を有効化。PNG ソース漫画では大幅にサイズ削減可能。レベルが高いほど小さいが遅い。JPEG ソースは効果が限定的で推奨しません（デフォルト `0` = 無圧縮）
- **検査モード** — `--inspect` で 1 冊の電子書籍をランダム抽出（`--inspect-all` で全冊）。CBZ を生成せず解凍して内部情報のみ読取: 基本検査（マジックバイト/サイズ/DRM 二重判定）、EXTH メタデータ（タイトル/著者/言語/出版日/出版社/ISBN/ASIN/著作権、見つかった場合のみ表示）、二重ディレクトリマーカー、OPF と spine の抽出数（先頭 5 ファイル名を縦並びプレビュー）、NCX 目次エントリ数とプレビュー、ディレクトリ内の全画像数、表紙（OPF guide 公式参照を優先、未ヒット時はファイル名一致にフォールバック）、画像形式分布、主流解像度（主流の高さ/幅 + もう一方の次元の範囲）、圧縮提案。DRM ヘッダーマーカーあり→直接 DRM と判定して解凍スキップ、マーカーなし+画像 0→疑いあり、マーカーなし+画像あり→なし。終了後は一時ディレクトリを自動クリーンアップ
- **元ファイルの任意削除** — `--delete` で変換成功後に元の電子書籍を自動削除
- **強制上書き** — `--overwrite` で既存の cbz を強制再生成。漫画を更新しても古いファイルを手動削除する必要がありません
- **単一ファイルタイムアウト保護** — `--timeout` で単一ファイルの変換時間を制限。破損/暗号化/巨大な電子書籍が下層の解凍を無限にブロックした場合、自動スキップして失敗として計上し、バッチ全体が停止しません（デフォルト 600 秒、`0` は無制限）
- **サイレントモード** — `--quiet` で一括変換時にエラーと集計のみ表示。`--log FILE` で全出力をログファイルに追記
- **簡潔な集計** — `--short-summary` で成功/スキップ/事前チェックスキップのファイルは件数のみ表示（失敗ファイルは常にフルパスで表示）。`--quiet` と相補的で、大規模ディレクトリ向け
- **DRM 暗号化検出** — DRM 暗号化された Kindle 漫画に遭遇した場合、静かに失敗せずに復号不可と明示
- **パス大文字小文字対応** — 表紙比較とディレクトリ整合に正規化された小文字パスを使用。大文字小文字を区別しない Windows ファイルシステムでも、命名の大文字小文字違いで重複/欠落を誤判定しません
- **出力タイムスタンプ** — 各行の出力に `[YYYY-MM-DD HH:MM:SS]` プレフィックスを自動付与。コンソールとログファイルで統一され、各変換の実行時刻を特定しやすい
- **カスタム出力ディレクトリ** — `--output-dir DIR` で CBZ を指定ディレクトリに出力（自動作成）。ソース電子書籍と同じディレクトリに強制されません
- **事前チェックフィルタリング** — 0 バイトやファイルヘッダ破損（オフセット 60 に `BOOKMOBI` マジックなし）の電子書籍は事前チェック段階で直接スキップ。ログにフルパスと理由を出力
- **最小サイズフィルタ** — `--min-size BYTES` で指定バイト数未満の電子書籍を除外（数値なしの場合はデフォルト 1000、`0` で無効、未指定でサイズフィルタ無効）。ヘッダーは完全だが内容が途中で切れた境界破損サンプルを補足
- **ドライランモード** — `--dry-run` で変換フローをスキャンして表示するのみ。実際の解凍・パッケージ化は行わず、事前に変換結果を確認したい場合に便利
- **所要時間統計** — 各ファイルの変換時間をリアルタイム出力。集計の下部に合計時間を表示

## 対応画像形式

変換時に以下の画像形式を認識してパッケージ化します: `.jpg` / `.jpeg` / `.png` / `.gif` / `.webp` / `.bmp` / `.tiff` / `.tif`

## 使い方

### 単一ファイルを変換

```bash
python manga-mobi2cbz.py "D:\Manga\Vol1.mobi"
```

### ディレクトリ全体を一括変換（.mobi / .azw / .azw3 を再帰検索）

```bash
python manga-mobi2cbz.py "D:\Manga"
```

### 変換成功後に元の電子書籍を削除

```bash
python manga-mobi2cbz.py "D:\Manga" --delete
```

### 二重ディレクトリ mobi で mobi7 を保持

```bash
python manga-mobi2cbz.py "D:\Manga\Vol1.mobi" --prefer mobi7
```

### ディレクトリ内の未収集の余分な画像を破棄

```bash
python manga-mobi2cbz.py "D:\Manga\Vol1.mobi" --drop-extra
```

### 既存の cbz がある場合に強制再生成

```bash
python manga-mobi2cbz.py "D:\Manga\Vol1.mobi" --overwrite
```

### 単一ファイル変換のタイムアウトを制限（破損ファイルによるバッチ停止を防止）

```bash
python manga-mobi2cbz.py "D:\Manga" --timeout 300
```

### カスタムディレクトリへ出力

```bash
python manga-mobi2cbz.py "D:\Manga" --output-dir "E:\CBZ"
```

### ドライラン: 変換フローをスキャンして表示するのみ（実際には変換しない）

```bash
python manga-mobi2cbz.py "D:\Manga" --dry-run
```

### サイレントモード + 出力をログに書き込み

```bash
python manga-mobi2cbz.py "D:\Manga" --quiet --log convert.log
```

### 簡潔な集計（大規模ディレクトリ、成功/スキップは件数のみ）

```bash
python manga-mobi2cbz.py "D:\Manga" --quiet --short-summary --log convert.log
```

### zip 圧縮を有効化（PNG ソース漫画で大幅にサイズ削減可能）

```bash
python manga-mobi2cbz.py "D:\Manga" --compress 9
```

### 検査モード: 1 冊の電子書籍の内部情報をランダム抽出（メタデータ/構造/画像/解像度/DRM/NCX 目次）

```bash
python manga-mobi2cbz.py "D:\Manga" --inspect
```

### 全電子書籍の内部情報を検査

```bash
python manga-mobi2cbz.py "D:\Manga" --inspect --inspect-all
```

### バージョン確認

```bash
python manga-mobi2cbz.py --version
```

## 出力

- デフォルトでは変換後の `.cbz` ファイルは元の電子書籍と同じディレクトリに配置。`--output-dir` 指定時はそのディレクトリに出力（自動作成）
- 既存の `.cbz` はデフォルトで自動スキップされ上書きされません。`--overwrite` で強制再生成
- 0 バイト / ファイルヘッダ破損の電子書籍は事前チェック段階で直接スキップ。ログにフルパスと理由を出力
- 各ファイルの変換時間をリアルタイム出力。集計の下部に合計時間を表示
- 変換に失敗したファイルはエラー情報を表示しますが、他のファイルの変換には影響しません

## 既知の制限

- **DRM 暗号化 mobi には非対応** — 下層の mobi ライブラリは Kindle ストアで購入した DRM 暗号化漫画を復号できません。該当ファイルは「DRM 暗号化の可能性あり」と明示してスキップされ、空の cbz が黙って生成されることはありません。変換前に DRM を解除してください
- **ComicInfo.xml は生成しない** — スクリプトは画像のパッケージ化のみを行い、変換成果物に ComicInfo.xml メタデータ（シリーズ、著者、タグ等）は含まれません。メタデータが必要な場合は別途注入してください
- **タイムアウト後のスレッド強制終了は不可** — 単一ファイルが `--timeout` を超えた場合、メイン処理はそのファイルをスキップして続行しますが、Python はブロックされた解凍スレッドを kill できません。スタックしたスレッドはプロセス終了まで残存し、メモリ/IO を占有し続けます。大量の破損ファイルを一括処理するとバックグラウンドにゾンビスレッドが蓄積する可能性があります。スタックしたタスクを完全に隔離するには `multiprocessing` による終了可能な子プロセス化が考えられますが、クロスプラットフォーム互換性の複雑さが増すため未採用です

## よくある質問

**Q: 変換後の CBZ で画像の順序が乱れているのは？**
A: OPF spine 順（EPUB 標準の読み順）で画像を抽出するため、ほとんどの場合順序は正しくなります。ソースに OPF が無い、または spine 抽出が空の場合はファイル名の自然順ソートにフォールバックします。それでも問題がある場合は、元の mobi 内部の画像命名が不統一な可能性があります。ソースファイルをご確認ください。

**Q: CBZ に表紙が無いのはなぜ？**
A: 一部の mobi では表紙が OPF metadata の cover meta にのみ指され、spine から参照されていないため、spine 順の抽出では漏れます。スクリプトはファイル名に cover/front を含む画像を自動スキャンし、欠落時に先頭へ補完します。表紙がすでに spine リスト内にある場合は元の順序を保持します。表紙ファイル名に上記キーワードが含まれない場合は漏れる可能性があるため、リネームして再変換してください。

**Q: 一部の mobi は変換後のサイズがとても小さいのはなぜ？**
A: 二重ディレクトリ mobi（mobi7+mobi8）はデフォルトで mobi8 のみ保持し、内容の重複によるサイズ倍増を防いでいます。mobi7 を保持したい場合は `--prefer mobi7` を指定してください。

**Q: 一括変換中に破損/暗号化 mobi で止まってしまう？**
A: 単一ファイル変換にはデフォルトで 600 秒のタイムアウトがあります（`--timeout` で調整可）。タイムアウト後は自動的にそのファイルをスキップして失敗として計上し、メイン処理は後続ファイルを続行します。ファイルが詰まっていることに早く気づいた場合は、`--timeout 30` のような小さめの値でスキップを速めるか、`--quiet` で出力を減らしてください。

**Q: .azw / .azw3 には対応していますか？**
A: 対応しています。v1.8.0 以降、入力拡張子は `.mobi` / `.azw` / `.azw3` に拡張され、3 形式とも同じ変換パイプラインを通ります。同一ディレクトリで同名・異拡張子の場合はデフォルトで azw3 を保持し、`--ext-priority` で調整できます。

## 更新履歴

### [1.8.0] - 2026-08-14

#### 追加

- 軽量多言語対応: `--language auto|zh-CN|zh-TW|ja|en`（デフォルト `auto` はシステム locale で自動判定: 簡体字→zh-CN、繁体字 zh-TW/zh-Hant→zh-TW、日本語 ja/Japanese→ja、非 zh/ja→en）。全出力文面と `--help` が言語に応じて翻訳（`--help` は `--language` を事前解析してから parser を構築する方式）。キー欠落時は en→キー名にフォールバックし例外を出さない。ビジネスコードに `if lang` 分岐は書かない。パラメータ名/列挙値/書籍 metadata/OPF/DRM/spine などの固有名詞は翻訳しない。タグ定数 `TAG_*` は全て削除し `t()` キーに置換
- `.azw` / `.azw3` 入力対応: 入力拡張子を `.mobi` / `.azw` / `.azw3`（大文字小文字区別なし）に拡張。3 形式とも共通の `extract → OPF/spine → 表紙 → 整合 → パッケージ → 検証` パイプラインを再利用し、並列実装なし
- `--ext-priority EXTS`: 同一ディレクトリ内で同名（拡張子のみ異なる）の場合に保持する形式——カンマ区切り、並び順が優先度（高い→低い）、`mobi`/`azw`/`azw3` のみ受け付け、デフォルト `azw3`。優先度が未指定のグループは azw3→mobi→azw にフォールバックし warning を出力。`--prefer`（二重ディレクトリ mobi7/mobi8 選択）とは完全に無関係

- マジックバイト事前チェックを 3 形式に拡張: オフセット 60 で `BOOKMOBI` マジックを統一的に検証。拡張子は正しいがマジックが誤っている（または `.azw/.azw3` でマジック異常）ファイルは「破損として直接スキップ」ではなく、warning を出力した上で解凍を試行（`mobi.extract` が二次検証を内蔵し、解凍失敗は通常通り失敗リストに計上）
